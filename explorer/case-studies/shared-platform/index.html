Case study 01 · Application architecture

One product. Multiple customers.

Replacing separate customer applications with a shared configurable codebase at Sentry Dynamics.

ProblemDuplicated fixes and feature work
ApproachShared application + configuration
OutcomeEasier maintenance and deployment
Context

The starting point

Each customer used a separate application: different versions of fundamentally similar software. When a shared bug needed fixing or a feature needed adding, engineering work had to be repeated in each application.

Design

Keep the common product together

I consolidated customer-specific codebases into one shared application. Configuration options controlled feature availability and presentation differences, including customer-specific styles. This retained customer flexibility without maintaining separate copies of shared functionality.

Architecture

A configurable shared application

Shared application code→Customer configuration→Features and styling

This is a conceptual diagram of the design, not an infrastructure diagram.

Impact

Reduced repeated work

The consolidation reduced duplicated development effort, made bug fixes and maintenance simpler, and eased deployment of updates. These are qualitative outcomes based on my experience; I have not published numerical estimates.

Takeaway

Engineering judgment

The important choice was identifying which behavior was truly shared and which variations should remain configurable. The resulting architecture made one product easier to evolve for multiple customers.
